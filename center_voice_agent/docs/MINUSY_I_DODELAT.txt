МИНУСЫ И ЧТО НАДО ДОДЕЛАТЬ — center_voice_agent
(по code review, май 2026)

================================================================================
ОРГАНИЗАЦИЯ КОДА
================================================================================

1. Всё в одном пакете — нет отдельного HTTP API (api/) и чёткого voice-модуля;
   CLI, пилот и ядро смешаны.

2. Два мира БД — runtime async SQLAlchemy + sync sqlite3 для publish режимов/
   сценариев; риск блокировок и путаницы «файл vs БД».

3. Новый AppContainer / engine на каждый AgentSession.open() — для ask_once
   в голосовом GUI лишняя нагрузка; нужен один контейнер на процесс.

4. Глобальное состояние — rate_limit._buckets и singleton LangGraph _compiled
   не масштабируются на несколько воркеров.

5. Tools через if/elif в factory.py — нет registry/MCP; каждый новый tool =
   правка кода.

6. Мёртвая таблица scenario_definitions — в схеме есть, код использует
   scenario_publish + YAML.

7. DX pytest — warning, если запускать не из корня center_voice_agent.


================================================================================
АРХИТЕКТУРА И ДОМЕН
================================================================================

8. AgentGateway всё ещё перегружен — prefetch, метрики, advance сценария.

9. Нет слоя HTTP/WebSocket — только CLI + integration/bridge.

10. Нет абстракции LLMProvider — по сути один OpenAI-совместимый клиент.

11. Coordinator завязан на внутренности gateway (session_messages_repository).

12. Смена режима по substring — ложные срабатывания; при смене/отказе режима
    LLM не вызывается, только шаблонный текст.

13. Сценарии — переходы по ключевым словам, без смысла ответа ребёнка.

14. state_json в session_state почти не используется — нет богатой state machine.

15. Краткая память: 15 сообщений, не 15 пар ходов — меньше контекста, чем
    может ожидать методист.


================================================================================
БЕЗОПАСНОСТЬ И COMPLIANCE (ДОДЕЛАТЬ)
================================================================================

16. Модерация слабая — только подстроки в YAML; перефраз обходит; нет ML/API,
    эскалации педагогу.

17. Rate limit только in-process — сброс при рестарте; несколько инстансов не
    защищены (нужен Redis).

18. web_search включён в детских режимах (dialog, play, lesson) при WEB_SEARCH_URL
    — выключить по умолчанию или взрослый режим.

19. ПДн в логах — аргументы tools (memory_upsert, поиск) в executed_tools;
    нужна политика redact/retention.

20. 152-ФЗ, трансграничность, согласия — не в коде; провайдер LLM, хостинг,
    процессы центра.


================================================================================
ИНФРАСТРУКТУРА И ДАННЫЕ
================================================================================

21. Миграции без schema_migrations — все SQL подряд; разбор по «;» хрупкий.

22. Пропуск файла 003 в нумерации — путает новичков.

23. SQL заточен под SQLite — для PostgreSQL отдельная ветка.

24. Кэш после publish — get_settings, scan сценариев; нужен reload в long-running.


================================================================================
LLM И ИНСТРУМЕНТЫ
================================================================================

25. text_tool_fallback — риск ложных вызовов tools на слабых моделях.

26. StaticChatModel — офлайн без tool_calls; нет E2E с tools на fake LLM.

27. Singleton LangGraph — ограниченная изоляция тестов.


================================================================================
ПРОДУКТ И SCOPE (НЕ В РЕПО / НЕ ГОТОВО)
================================================================================

28. STT/TTS — вне пакета (voice_assistant).

29. Веб / личный кабинет — нет.

30. RAG / методички центра — нет.

31. MCP registry — только в docs.

32. PostgreSQL + Alembic — нет.

33. NLU для смены режима — вместо substring.

34. HTTP API (POST /turn, WebSocket) — нет.

35. Пилот с детьми — задел есть, для compliance недостаточно без P0.
